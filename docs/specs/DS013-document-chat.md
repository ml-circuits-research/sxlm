## Introduction

The Chat view lets a reader attach a document, wait for processing and ask English questions about its interpreted contents. The user does not author [circuits](../wiki.html#definition-circuit) or manually activate a candidate. A coding agent prepares conversation-local [SOP](../wiki.html#definition-sop) knowledge offline; ordinary replies execute the resulting symbolic model locally.

## Core Content

### Attachment and conversation contract

Chat must open as the workbench's default view. Its principal controls are a conversation selector, a new-conversation button, an attachment button, a message field and a send button. Attachment selection must begin upload and processing automatically. The interface must show upload progress, reading, coding, verification, readiness or an actionable failure. Processing logs and evidence must remain optional details. A ready indicator must require successful validation and activation in that conversation.

The workbench must persist conversations, source metadata, turns, model-bound snapshots, [extraction](../wiki.html#definition-extraction) records, job states and validation [receipts](../wiki.html#definition-receipt) under `.sxlm/chat` using [SOP](../wiki.html#definition-sop). Raw attachments, extracted text and process logs retain their native byte or text representation. Transcript pages must exclude snapshots and load full evidence separately. Restoring an unchanged model must restore its snapshot. Adding a checked document must reconstruct the model and replay retained observations before changing the active conversation [context](../wiki.html#definition-context); earlier answers retain their original model identity. A [budget](../wiki.html#definition-budget) failure during replay must prevent activation.

Every conversation must retain its own base model identity and ordered [pack](../wiki.html#definition-pack) artifacts under `.sxlm/chat/models`. A new version of the general knowledge library applies to new conversations; it must not silently change the interpretation, dependencies or document [packs](../wiki.html#definition-pack) of an existing conversation. Archive reconstruction must verify every [pack](../wiki.html#definition-pack) hash and reproduce the original model and runtime identities. An older conversation without an archive may recover its base from a retained coding packet only when that packet's reference [packs](../wiki.html#definition-pack) reconstruct exactly the recorded parent. A missing or incompatible runtime requires explicit migration and revalidation. One damaged conversation must not prevent unrelated conversations from opening.

A temporary failure while polling an active job must schedule another status read and clear the connection message after recovery. This recovery must not repeat uploads, messages or coding-job creation. Switching to another conversation must stop polling the previous view; the server-owned job continues independently.

New school conversations must install the authored elementary knowledge, the qualified `everyday-knowledge` extension and the supervised `english-constructions` [pack](../wiki.html#definition-pack). `elementary: false` must disable all three additions. Installing this profile must not alter archived conversations or run a coding agent during ordinary messages. The construction vocabulary supplies `owned` and `helped`. The learned predicate must compose through the existing copula, negation and question [circuits](../wiki.html#definition-circuit); other participles and tense distinctions require separate supervision.

### Formats and source identity

Uploads must use independently numbered fragments of at most 65,536 bytes. Repeating a committed fragment must require identical bytes. There is no application-wide total upload byte cap; disk space and downstream processing remain finite. Text fragments must be valid UTF-8. Binary attachments must retain their exact uploaded bytes. Finalization must bind the concatenated attachment hash before processing.

The attachment path supports UTF-8 text, Markdown, CSV, TSV, HTML and XML; PDF; DOCX, PPTX and XLSX; and supported image formats through English OCR. Format selection governs document decoding, not language reasoning. PDF [extraction](../wiki.html#definition-extraction) uses `pdftotext`; Open XML office [extraction](../wiki.html#definition-extraction) uses Python standard-library XML and ZIP readers; image [extraction](../wiki.html#definition-extraction) uses `tesseract`. These optional host tools are outside the inference runtime. Missing tools or unsupported formats must fail explicitly. Spreadsheet formulas and document macros must not execute.

[Extraction](../wiki.html#definition-extraction) must retain the original attachment, a content identity for extracted text and the extractor identity or source identity. Office [extraction](../wiki.html#definition-extraction) must preserve available part, slide and worksheet labels; spreadsheet cell coordinates and formula-cache caveats must remain visible. Layout, merged cells, embedded diagrams, OCR errors and PDF reading order are limitations of the extracted representation. A scanned PDF without extractable text requires an OCR text export or page images. Text spans are UTF-16 offsets into extracted text, not visual page rectangles.

The host must archive extracted source fragments outside the coding agent's writable workspace before starting that agent. The agent receives a copy. Fact and rule evidence must match the protected [extraction](../wiki.html#definition-extraction), including any contiguous source window across at most eight fragments. Editing a working copy must not change the evidence archive or validate a fabricated span. [Extraction](../wiki.html#definition-extraction) fidelity and semantic interpretation fidelity remain distinct from exact source attribution.

### Coding packet and execution

Document processing must create an isolated job workspace with the original attachment, extracted sources, [extraction](../wiki.html#definition-extraction) limitations, the actual parent identity and manifests, installed [grammar](../wiki.html#definition-grammar), relevant DS contracts, a copied compiler/runtime reference and an offline SDK. The task instructions must treat document contents as untrusted evidence and preserve polarity, roles, dates, units, table [context](../wiki.html#definition-context), attribution, ambiguity and [coverage](../wiki.html#definition-coverage). They must prohibit native inference edits, whole-question answer tables, unrelated file access and relabeling authored observations as induced knowledge.

The SDK's `compileDocument` accepts constant lexical `phrases` alongside facts, rules, [grammar](../wiki.html#definition-grammar) and [SOP](../wiki.html#definition-sop) policies. Phrase compilation must bind the exact parent tokenizer and preserve both phrase and ordinary [grammar](../wiki.html#definition-grammar) [providers](../wiki.html#definition-provider). Agent instructions must require inspection of existing category contracts, shared terminology representations, novel compositions, counterexamples and measurements under default request [budgets](../wiki.html#definition-budget). An authored term dictionary must not become a whole-question answer table. A capacity failure must remain a failure; increasing limits or hiding interpretation gaps must not count as successful compilation.

A real `codex exec` process must author and test `candidate.sop`. Its sandbox must be `workspace-write`; its writable root must be the job workspace. Only the inert [SOP](../wiki.html#definition-sop) candidate crosses into the host model. Agent-authored JavaScript may compile a candidate offline but must never become inference code. Structured teaching and test artifacts must use [SOP](../wiki.html#definition-sop). [Codex](../wiki.html#definition-codex) authentication and network access belong to the offline coding environment; inference must not fall back to a remote language model.

Jobs must move through queued, preparing, running, validating and ready, or a recorded failed, cancelled or interrupted state. The workbench executes at most two jobs simultaneously and admits one pending job per conversation. Additional conversations enter a first-in, first-out queue and start automatically when capacity is available. The 20-minute operational time limit starts when processing begins and excludes queue time. Cancelling a queued job must prevent launch; cancelling an executing job must stop the tracked process group. A restarted workbench must distinguish terminal or interrupted jobs from a still-owned active process. Failures must retain diagnostics and must not activate partial knowledge.

A rejected candidate permits one automatic correction by the coding agent, within the same operational deadline. The host supplies `validation.sop` with rejected artifact hashes, the contract error, remaining time and any procedural status/cost diagnostics. Gate questions and expected answers must remain outside that feedback. Each available candidate, compiler script, agent result and validation record must be archived outside the writable job workspace. Both attempts must use the same source, parent, request [budgets](../wiki.html#definition-budget) and full validator. A process launch failure, cancellation, elapsed deadline or activation failure must terminate processing without an automatic correction. A passing candidate validation record does not establish activation; conversation replay and a live deadline remain required. Adaptive correction feedback must not be described as blind evaluation.

### Validation and activation

A document candidate must bind its actual parent and original/extracted source identities. It may supply fact, theory and [grammar](../wiki.html#definition-grammar) [providers](../wiki.html#definition-provider), but it must not replace task entrypoints, [linkage](../wiki.html#definition-linkage) definitions or existing module identities. Every new fact and rule must have exact attribution to the uploaded or protected extracted source. The model must install the candidate as typed [SOP](../wiki.html#definition-sop) before it can be accepted.

Candidate validation must run in a separate host process. Protected [SOP](../wiki.html#definition-sop) request/response artifacts must bind the actual parent [packs](../wiki.html#definition-pack), parent identity, candidate bytes, uploaded document and protected [extraction](../wiki.html#definition-extraction). The worker must load the trusted repository validator; agent-authored native code and modified reference copies must not execute. Default model [budgets](../wiki.html#definition-budget) and all source/procedure checks remain unchanged. The server must remain available for status reads and cancellation while validation runs. A worker launch, protocol or parent-identity failure must stop the job rather than ask the coding agent to conceal an infrastructure failure.

New observations can legitimately change truth and selection answers. Procedural regression checks must therefore retain the candidate's [grammar](../wiki.html#definition-grammar) and policy modules while ablating that document's newly supplied facts and rules. The [receipt](../wiki.html#definition-receipt) must name this profile explicitly. Source checks evaluate the actual unablated knowledge separately. This conversation-local interpretation contract must not replace or weaken the independent improvement, transfer, leakage and regression gates for global learning [promotion](../wiki.html#definition-promotion) in DS008.

Successful validation must automatically activate the [pack](../wiki.html#definition-pack) only in its originating conversation. Existing observations must survive model reconstruction. A stale parent, changed candidate content or failed replay must block activation. Logical replies must retain the ordinary [certificate](../wiki.html#definition-certificate), [coverage](../wiki.html#definition-coverage) and resource contracts. Coding-agent interpretation plus constructor compilation is authored supervision, not proof of induced language competence or independently established source truth.

An operator may request `POST /api/chat/:id/jobs/:job/recheck` for a failed job with a protected candidate and the unchanged conversation parent. Rechecking must create a distinct queued operation, verify the archived candidate byte hash and rerun the complete isolated validator. It must preserve the original failure record and coding provenance. The operation must identify `codex-artifact-revalidation` and `revalidationOf`; it must not claim another coding-agent execution or relax model [budgets](../wiki.html#definition-budget). Successful rechecking uses the ordinary activation and replay guards. The simple UI's Retry action starts a new [coding job](../wiki.html#definition-coding-job).

### Capacity and evidence boundary

The ordinary [pack](../wiki.html#definition-pack) limit is 8 MiB, flat [provider](../wiki.html#definition-provider) [linkage](../wiki.html#definition-linkage) is limited to 127 [providers](../wiki.html#definition-provider), and model request [budgets](../wiki.html#definition-budget) remain those of DS002. Large upload support does not establish unlimited model capacity, unlimited agent [context](../wiki.html#definition-context) or general long-document understanding. The coding agent must disclose unrepresented material and ambiguities. Validation [receipts](../wiki.html#definition-receipt) must retain its declared interpretation limitations, and Processing details must expose them alongside [extraction](../wiki.html#definition-extraction) limitations. The elementary [pack](../wiki.html#definition-pack) supplies source-supervised introductory facts, rules and compositional language; its finite evaluation does not establish unrestricted child-level conversation.

The implementation contracts are exercised by `test/chat-store.test.mjs`, `test/chat-integration.test.mjs`, `test/chat-repair.test.mjs`, `test/document-extraction.test.mjs` and `test/elementary-knowledge.test.mjs`. Actual coding-process evidence belongs in `reports/chat-live-demo.sop`; browser evidence and additional attachment checks must identify their exact model and artifact. Compatibility with sibling experiments requires separately owned evaluation cases; this interface alone does not establish that [coverage](../wiki.html#definition-coverage).

The two-sheet workbook probe in `reports/chat-xlsx-live.sop` records 8/8 source-grounded questions after isolated revalidation of an actual [Codex](../wiki.html#definition-codex)-authored artifact. It includes role selection, locations, a positive rule, an explicit negative rule and unknown counterexamples. `reports/chat-xlsx-before-validation-isolation.sop` retains both earlier resource failures. This result must be attributed to archived-artifact revalidation, not another [Codex](../wiki.html#definition-codex) execution. The fixture and expected questions share project authorship and do not establish general spreadsheet understanding.

The optional elementary knowledge version 4 contains 114 source-supervised domain facts, 65 explicit category declarations, 129 rules, 34 [grammar](../wiki.html#definition-grammar) productions and ten authored policies. Its 27 references accompany the teaching statements and explicitly declared relation assumptions. Arithmetic word forms reuse exact expression evaluation; taxonomy rules compose with user observations; named calendar questions query an explicit adjacent-cycle relation and its inverse. The cycle contract permits several values when a supplied relation branches and leaves missing values unknown. Qualitative temporal order is a separate relation and does not imply date arithmetic or event-state updates. Forty-seven elementary capability probes, 29 relational probes and separate extension/[ablation](../wiki.html#definition-ablation) checks exercise the library. The imported school cases were development-visible before this revision and cannot serve as blind validation. Source compilation must remain distinguished from program induction and unrestricted child-level conversation.

### Explicit query-only base migration

An explicit maintenance migration may update the base of a conversation containing only queries, with no documents, jobs or committed observations. It must inspect the complete history, verify retained snapshots against their archived base, require the same native runtime, replay the questions without committing observations or exhausting their [budgets](../wiki.html#definition-budget), archive the target base and retain a [receipt](../wiki.html#definition-receipt) containing the previous conversation record and original turn hashes. Original turn files and model archives must remain unchanged. This bounded operation does not authorize automatic document migration or silent reinterpretation of observations.

### Attach a document and talk about it

Open the workbench at `http://127.0.0.1:3210`. Chat is the default view. Use the attachment button beside Message, select a file and wait for “Ready — ask me about it.” The workbench reads the attachment, asks [Codex](../wiki.html#definition-codex) to create [SOP](../wiki.html#definition-sop) [circuits](../wiki.html#definition-circuit), checks the interpretation in a separate process and adds it to that conversation automatically.

#### Files and questions

Attach a PDF, Word document (`.docx`), presentation (`.pptx`), workbook (`.xlsx`), supported image or UTF-8 text file. Text includes Markdown, CSV, TSV, HTML and XML. A pasted message longer than 16,000 UTF-16 characters is uploaded as a text attachment. Each attachment is processed in fragments, so the upload does not depend on the ordinary structured-request size limit.

Once processing finishes, ask questions in the Message field. Press Enter to send or Shift+Enter for a newline. A new conversation starts with the installed introductory knowledge [pack](../wiki.html#definition-pack); additional documents belong to the selected conversation. Existing conversations retain their captured model when the general library is extended. Start a new conversation to use a newer general knowledge version. For example, a document stating “Cedar is a pilot. Every pilot is careful.” can support “Is Cedar careful?” through an explicit rule and source-backed proof.

#### Reading a response

Messages remain available after restarting the workbench. Evidence opens the interpretation and proof for a reply. Processing details opens [extraction](../wiki.html#definition-extraction) limitations and the coding log; it is also where a queued or running job can be cancelled. If two documents are being processed, another conversation's attachment waits and starts automatically. If a candidate fails validation, the agent receives the diagnostic and can correct it once while the interface shows “Refining the interpretation…”. Both attempts share the 20-minute limit. A remaining failure keeps the attachment stored, and Retry starts another [coding job](../wiki.html#definition-coding-job).

Formal proofs establish consequences of the represented interpretation. The coding agent can misinterpret a source, and document [extraction](../wiki.html#definition-extraction) can lose layout or characters. A [source span](../wiki.html#definition-source-span) verifies attribution to the extracted text. Unsupported questions and ambiguous interpretations remain visible instead of receiving invented answers.

#### Local setup and limits

The symbolic model requires Node.js 22 or later. Document teaching additionally requires an authenticated `codex` executable available on the server's path. PDF [extraction](../wiki.html#definition-extraction) uses `pdftotext`, office [extraction](../wiki.html#definition-extraction) uses `python3`, and image OCR uses `tesseract` with English language data. These tools run while preparing a document; ordinary symbolic replies do not call [Codex](../wiki.html#definition-codex).

There is no total upload byte cap in the application. Disk capacity, [extraction](../wiki.html#definition-extraction) time, [Codex](../wiki.html#definition-codex) [context](../wiki.html#definition-context), the 20-minute job limit, the 8 MiB [pack](../wiki.html#definition-pack) limit and model reasoning [budgets](../wiki.html#definition-budget) still constrain processing. A large file can therefore upload successfully and fail to become a usable symbolic interpretation. Scanned PDFs without text need an OCR export or separate page images. Spreadsheet formula caches can be stale, and formulas never execute during [extraction](../wiki.html#definition-extraction).
#### Category questions

New conversations use the installed elementary model and support category questions such as `What are cats?` and `Is a cat an animal?`. Descriptions report the classification statements supported by the model; they do not invent an animal's properties. Existing conversations retain their archived base and document interpretations by default. An explicit, recorded revalidation can update a query-only conversation while preserving its original turns and base archive. Starting a new conversation uses the updated base without changing older answers or validated document artifacts.

The document SDK accepts `concepts` and source-attributed `inclusions` alongside facts, rules and phrases. Agents supply actual noun forms and distinguish universal class relations from observations about individuals. The same validation checks source attribution and prior procedures before activation. A legacy base without `knowledge.concepts` cannot use this compiler path.
#### Learned phrase composition

New conversations also understand phrases such as “Pico is owned by Mira” and “Pico is not helped by Mira,” and questions such as “Is Pico owned by Mira?” The same learned procedure preserves actor roles when these phrases occur inside supported rules or attributed beliefs. Its lexical forms and six example meanings are supplied teaching data; the composition procedure is induced and deployed as [SOP](../wiki.html#definition-sop). Existing conversations retain their archived models. Start a new conversation to use a newly installed profile without changing the meaning of retained documents or statements.
#### Properties and intended uses

New conversations also support “What do eyes help us do?”, “What is a pencil used for?”, “What do plants need?” and “What do plants usually need?”. Selected source-backed knowledge supplies the answers. Typical requirements remain qualified; a type's intended function does not establish an individual object's working condition. The library is nonexhaustive, and unsupported wording can still produce an interpretation gap.

Document teachers may supply `properties` with a concept, relation, values, explicit polarity, `definition`, `all-instances` or `typical` mode, and exact attachment spans. The compiler preserves that qualification and emits ordinary SOP knowledge. Agents must supply any additional terminology or question syntax separately and disclose source interpretation limits. Existing document conversations remain bound to their archived vocabulary and model.
