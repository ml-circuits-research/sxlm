Attach a document and talk about it

Open the workbench at http://127.0.0.1:3210. Chat is the default view. Use the attachment button beside Message, select a file and wait for “Ready — ask me about it.” The workbench reads the attachment, asks Codex to create SOP circuits, checks the interpretation in a separate process and adds it to that conversation automatically.

Files and questions

Attach a PDF, Word document (.docx), presentation (.pptx), workbook (.xlsx), supported image or UTF-8 text file. Text includes Markdown, CSV, TSV, HTML and XML. A pasted message longer than 16,000 UTF-16 characters is uploaded as a text attachment. Each attachment is processed in fragments, so the upload does not depend on the ordinary structured-request size limit.

Once processing finishes, ask questions in the Message field. Press Enter to send or Shift+Enter for a newline. A new conversation starts with the installed introductory knowledge pack; additional documents belong to the selected conversation. Existing conversations retain their captured model when the general library is extended. Start a new conversation to use a newer general knowledge version. For example, a document stating “Cedar is a pilot. Every pilot is careful.” can support “Is Cedar careful?” through an explicit rule and source-backed proof.

Reading a response

Messages remain available after restarting the workbench. Evidence opens the interpretation and proof for a reply. Processing details opens extraction limitations and the coding log; it is also where a queued or running job can be cancelled. If two documents are being processed, another conversation's attachment waits and starts automatically. If a candidate fails validation, the agent receives the diagnostic and can correct it once while the interface shows “Refining the interpretation…”. Both attempts share the 20-minute limit. A remaining failure keeps the attachment stored, and Retry starts another coding job.

Formal proofs establish consequences of the represented interpretation. The coding agent can misinterpret a source, and document extraction can lose layout or characters. A source span verifies attribution to the extracted text. Unsupported questions and ambiguous interpretations remain visible instead of receiving invented answers.

Local setup and limits

The symbolic model requires Node.js 22 or later. Document teaching additionally requires an authenticated codex executable available on the server's path. PDF extraction uses pdftotext, office extraction uses python3, and image OCR uses tesseract with English language data. These tools run while preparing a document; ordinary symbolic replies do not call Codex.

There is no total upload byte cap in the application. Disk capacity, extraction time, Codex context, the 20-minute job limit, the 8 MiB pack limit and model reasoning budgets still constrain processing. A large file can therefore upload successfully and fail to become a usable symbolic interpretation. Scanned PDFs without text need an OCR export or separate page images. Spreadsheet formula caches can be stale, and formulas never execute during extraction.

Category questions

New conversations use the installed elementary model and support category questions such as What are cats? and Is a cat an animal?. Descriptions report the classification statements supported by the model; they do not invent an animal's properties. Existing conversations retain their archived base and document interpretations by default. An explicit, recorded revalidation can update a query-only conversation while preserving its original turns and base archive. Starting a new conversation uses the updated base without changing older answers or validated document artifacts.

The document SDK accepts concepts and source-attributed inclusions alongside facts, rules and phrases. Agents supply actual noun forms and distinguish universal class relations from observations about individuals. The same validation checks source attribution and prior procedures before activation. A legacy base without knowledge.concepts cannot use this compiler path.

Learned phrase composition

New conversations also understand phrases such as “Pico is owned by Mira” and “Pico is not helped by Mira,” and questions such as “Is Pico owned by Mira?” The same learned procedure preserves actor roles when these phrases occur inside supported rules or attributed beliefs. Its lexical forms and six example meanings are supplied teaching data; the composition procedure is induced and deployed as SOP. Existing conversations retain their archived models. Start a new conversation to use a newly installed profile without changing the meaning of retained documents or statements.
